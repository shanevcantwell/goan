# Design Doc: Draggable Task Queue Reordering

-   **Author**: Gemini Code Assist
-   **Date**: 2024-07-26
-   **Status**: Proposed

---

## 1. Summary

This document proposes a significant user experience enhancement for the task queue: replacing the current single-step "up/down" arrow controls with a modern, intuitive drag-and-drop reordering system.

---

## 2. Problem: The "Slow Step" and Interaction Model

The current method for reordering tasks in the queue requires the user to click an up or down arrow for each single position change. Each click triggers a full server-side update and a refresh of the Gradio `DataFrame` component.

To ensure stability during generation, this interaction model includes several logical constraints:
-   **Reordering is limited to `pending` tasks.**
-   **The "currently processing" task (at index 0) is locked** and cannot be moved or edited.
-   **No other task can be moved into the "currently processing" slot.** This prevents a user from swapping the active task mid-generation.

While these constraints make the queue robust, they do not address the core usability issue: the single-step interaction model is inefficient and feels slow, especially when moving a task over long distances in a large queue. This creates a poor user experience and feels out of place in a modern, responsive UI.

---

## 3. Proposed Solution: Drag-and-Drop Rows

The proposed solution is to implement drag-and-drop functionality directly on the rows of the task queue `DataFrame`.

-   **User Interaction**: A user would be able to click and hold on a task row, drag it to a new position in the queue, and release it to finalize the move.
-   **Efficiency**: This single action would replace multiple clicks and server round-trips. The backend would only be updated once, after the drop is complete, with the new full order of the queue.
-   **Intuitive Design**: This is a standard and widely understood UI pattern for reordering lists, making the application more intuitive for all users.

---

## 4. Implementation Considerations & Challenges

Implementing this feature presents a notable technical challenge, as Gradio's `gr.DataFrame` component does not natively support row dragging. The implementation would likely require:

1.  **Custom JavaScript**: A significant amount of custom JavaScript would need to be written to handle the drag-and-drop events on the HTML table generated by Gradio. Libraries like `SortableJS` could be leveraged for this.
2.  **JS-to-Python Communication**: The JavaScript would need to communicate the new order of the task IDs back to the Python backend when a drop event occurs. This can be achieved using Gradio's `_js` parameter functionality.
3.  **Backend Handler**: A new Python event handler would be needed to receive the new queue order from the JavaScript and update the `QueueManager` state accordingly.

While complex, this feature would represent a major leap forward in the application's usability and is a high-value target for future development.
